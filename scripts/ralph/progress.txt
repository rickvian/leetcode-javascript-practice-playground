## Codebase Patterns
- Test runner: Project uses Vitest (not Jest) — run tests with `npx vitest run <path>` or `npm test`
- LeetCode file naming: [number]-[problem-name].js (e.g., 0001-two-sum.js)
- Function exports: Use ES Module syntax `export { functionName }` (NOT CommonJS module.exports)
- TreeNode problems: Define TreeNode class in solution file and export it alongside function
- LinkedList operations: Create helper ListNode class for linked list problems; define arrayToList/listToArray helpers in test file
- Tree problems: Export TreeNode class from solution file for use in tests
- Stub tests: All tests "fail" for stub files (expected - implementations are blank); guard assertions with `if (result !== undefined)`
- In-place array problems: Verify both return value (k) and modified array slice — pattern: expect(k).toBe(n); expect(nums.slice(0, k)).toEqual([...])
- Array index search problems: Sort result arrays before comparing when order is not guaranteed — pattern: expect(result?.sort((a,b) => a-b)).toEqual([...])
